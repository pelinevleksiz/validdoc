## 3. Input Specifications

**Automated backend tests (TC-AUTH through TC-RET, TC-SMOKE, TC-CTX):** inputs are constructed directly in test code — synthetic user credentials, template/segment definitions, and document files (PNG/JPEG/PDF, including deliberately malformed and boundary-case files) built or loaded within the test method itself. No external fixture files are required; each test is self-contained.

**Automated frontend tests (TC-FE):** inputs are simulated user interactions (typing, clicking, file selection via `userEvent`) against components rendered with `renderWithProviders`; the backend API is mocked at the module boundary (`vi.mock("@/lib/api")`), so no live backend is required.

**Manual accuracy campaign (TC-MAN):** inputs are the 48 documents generated by `SyntheticDocumentGenerator` (4 templates × 4 fill variants × 3 quality levels) plus a small set of genuinely scanned/handwritten documents, matched against expected values recorded in `target/synthetic-documents/manifest.csv`.

## 4. Output Specifications

**Automated tests:** pass/fail is determined by JUnit 5 / Vitest assertion outcomes (HTTP status codes, response body fields, DOM element presence/absence, mock call arguments, as specified per test case below).

**Manual accuracy campaign:** output is a per-segment comparison of actual engine outcome against expected outcome, classified as `MATCH`, `MISMATCH`, or `NEEDS_REVIEW` (the latter when the actual document/segment status is `PENDING_REVIEW`), recorded in `target/campaign-results/campaign-results.csv` and summarized in `target/campaign-results/campaign-summary.md`.

## 5. Environmental Needs

See Test Plan §11. Automated backend tests require Testcontainers-provisioned PostgreSQL; automated frontend tests require only Node.js/Vitest with jsdom; the manual accuracy campaign requires the full stack running via `docker compose up`.

## 6. Special Procedural Requirements

- Backend integration tests within `ApiIntegrationTest` are order-dependent (`@Order` annotations) where later tests rely on state created by earlier ones (e.g., template or user records); they must be run as a complete class, not individually, to guarantee valid preconditions.
- The manual accuracy campaign (TC-MAN) requires manual preparation of genuinely scanned/handwritten documents outside the automated toolchain: printing a blank template, physically completing it by hand under varying legibility conditions, and scanning or photographing the result. This preparation is outside the scope of any automated tool in this project.
- The `AccuracyCampaignRunner` tool automatically regenerates the synthetic document set via `SyntheticDocumentGenerator` if `target/synthetic-documents` is absent, and automatically retries uploads that are rejected by the system's own rate limiter (HTTP 429) with a 65-second backoff.

## 7. Intercase Dependencies

Within `ApiIntegrationTest`, the following notable dependencies exist between test cases (non-exhaustive; see individual `@Order` sequencing in source for the complete chain):

- TC-TPL-002 (`adminCanCreateValidTemplate`) creates a template subsequently read by TC-TPL-003 (`templateDetailReturnsSegmentAndRule`).
- TC-TPL-008 (`adminCanCreateInkOnlyTemplate`) creates the template used by TC-UPL-004, TC-UPL-005, TC-UPL-007, TC-UPL-008, TC-UPL-010, and TC-UPL-011.
- TC-UPL-006 (`pageMismatchRoutesToPendingReview`) creates the inconsistent multi-page template reused by TC-UPL-009 and TC-REV-010.
- TC-REV-002 (`resolveTestTemplateAndDocumentAreSeededAsPendingReview`) seeds the pending document and segments consumed by TC-REV-003 through TC-REV-009.
- TC-REV-007 (`resolvingLastPendingSegmentRecomputesDocumentStatus`) produces the resolved-segment state consumed by TC-REV-011, TC-REV-014, and TC-REV-015.
- TC-SET-001 (`validationSettingsCanBeReadAndUpdatedByAdmin`) produces the audit log entry read by TC-AUD-001.

The frontend test files (TC-FE) have no intercase dependencies; each test independently mounts its component tree via `renderWithProviders`.

The manual campaign (TC-MAN) has no dependency on the automated suite, but its tooling (`AccuracyCampaignRunner`) depends on `SyntheticDocumentGenerator`'s output format (`manifest.csv` columns) remaining stable.
